# 视频结果页设计

日期：2026-09-17。用户希望通过 URL 查看每个视频生成的 `result.json`、`summary.md` 和相关产物。首版只在服务器 `127.0.0.1` 监听，由 Windows 使用 SSH 端口转发访问 `http://localhost:8765`；不开放公网端口。

## 方案选择

- **采用：Python 标准库只读 HTTP 服务 + 原生 HTML/CSS/JavaScript。** 直接读取现有 `runs` 目录，依赖少，适合当前单机批处理 MVP。
- 备选：FastAPI + 前端构建工具。组件化和接口扩展更方便，但会增加部署依赖和构建流程。
- 备选：静态导出每次结果。部署最简单，但新增视频后必须重新生成站点，也不便于统一列出多次运行。

## 页面与数据流

服务器扫描 `runs` 的直接子目录，仅把同时具有可解析 `result.json`、`summary.md` 和 `manifest.json` 的目录作为运行记录。按 manifest 中的输入 SHA-256 聚合为视频；显示输入文件名、分析时间、模型、完整/部分状态和事件数。默认选择最近一次完整运行。

详情页展示摘要、事件时间线、每个事件的证据图、原始 JSON，以及 `summary.md`、`result.json`、`manifest.json` 的下载链接。浏览器只调用同源 API，不依赖 CDN。摘要仅解析本项目使用的标题、段落和列表语法，所有模型文本以 DOM `textContent` 写入，避免当作 HTML 执行。

## 只读与访问边界

服务进程只能从配置的 `runs` 根目录读取已发现的运行目录。证据图必须由 `result.json` 中的相对路径引用，不能通过 URL 读取任意服务器文件。API 不提供删除、上传或修改功能。监听地址固定为 `127.0.0.1`；SSH 登录与本地端口转发是访问前提。

## 验证

用临时运行目录测试视频聚合、缺失/损坏结果过滤、路径穿越拒绝、摘要和 JSON 下载、证据帧引用限制。部署后从 Windows 通过 SSH 隧道实际打开页面，并核对 `sample-full` 的 11 个事件和 44 张证据帧。
