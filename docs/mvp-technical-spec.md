# 本地视频内容理解与人物关联 MVP 技术规格

状态：待实施  
日期：2026-09-16  
目标：输入一段本地视频，离线生成可回溯的任务/动作时间线、视频摘要，并给同一视频中反复出现的人分配尽量稳定的匿名 ID。

## 1. 背景与决策

视频大模型负责回答“发生了什么”，专门的检测、跟踪与重识别模块负责回答“画面中的人是否再次出现”。最终文字只能引用已记录的事件和人物 ID；证据不足时输出“未确认”，不能猜测真实姓名、任务已完成或两个人必然相同。

本 MVP 是**单文件、离线、批处理**工具。优先验证结果质量和数据结构，再考虑实时流、Web 页面、批量任务队列及模型微调。

### 1.1 约定与待验证假设

- 输入：本地 MP4/MOV，单文件不超过 10 分钟、1080p，1–5 人为主要场景；超过该范围可以尝试处理，但不列入 MVP 验收。
- 运行环境：远程 Ubuntu 20.04.5 服务器提供 1 张 NVIDIA L20（`nvidia-smi` 报告 46068 MiB 可用显存，驱动 580.178.04）、100 GB 内存、22 核 CPU；开发机为 Windows。系统 Python 为 3.8.10，需在项目虚拟环境中使用较新的 Python；FFmpeg 4.2.7 已安装，根分区剩余约 259 GB（2026-09-16 检查）。服务器运行模型，Windows 负责编辑与轻量测试；上下文过长时改用 4B、量化、降低帧采样和缩短片段。
- 语言：输出简体中文；语音以中文为主，混合英文允许原文保留。
- 人物身份：仅在**当前视频内**使用 `P1`、`P2` 等匿名 ID；不建实名人脸库，也不跨视频关联。
- “任务”指画面或声音能支持的可观察活动；若业务有固定任务清单，通过配置传入。任务是否完成须有明确证据，否则状态为 `进行中` 或 `无法判断`。
- 所有处理在本机完成。首次安装和下载模型需要网络；运行时不调用云 API。

## 2. 范围

### 2.1 必须具备

1. 接收一个视频路径，校验格式、时长、解码能力并生成任务目录。
2. 提取镜头边界、带时间戳的采样帧和音轨。
3. 检测人物、镜头内跟踪，处理短暂遮挡；跨镜头尝试重识别，无法确认时保留独立 ID。
4. 若存在语音，进行本地转写；转写内容作为事件理解的辅助证据。
5. 按片段识别人物的可观察动作、对象、时间范围及任务状态。
6. 生成 `result.json`、`summary.md`，其中事件可追溯到时间点和采样帧。
7. 保存模型版本、参数和运行日志，使同一输入的结果可复查。

### 2.2 MVP 不包含

- 真实姓名识别、跨视频人脸库、身份验证。
- 直播实时分析、自动报警、监控式人员检索。
- 对看不见的结果作推断，例如仅凭“开始安装”判断“安装完成”。
- 训练业务专用模型、自动把语音说话人绑定到画面人物。

## 3. 技术选型

| 模块 | 首选 | 用途与选择理由 |
| --- | --- | --- |
| 解码/切段 | FFmpeg + PySceneDetect | 音视频抽取与镜头切分；保留原始时间轴。 |
| 视频理解 | Qwen3-VL-8B-Instruct；低显存时 4B | 中文描述、视频问答和结构化事件抽取；本地权重可用。 |
| 人体检测 | RT-DETR | 每个采样/跟踪帧输出人体框。 |
| 镜头内跟踪 | BoT-SORT | 将连续帧的人体框连接为 tracklet，支持外观信息辅助关联。 |
| 跨镜头关联 | FastReID 外观向量 + 规则 | 比较同视频不同 tracklet；相似度阈值需用样本校准。 |
| 语音转写 | faster-whisper | 本地转写及语音片段时间戳。 |
| 数据与产物 | JSON 文件 + 本地帧图 | MVP 无需数据库；保留审查证据。 |

参考：[Qwen3-VL](https://github.com/QwenLM/Qwen3-VL)、[RT-DETR](https://github.com/lyuwenyu/RT-DETR)、[BoT-SORT](https://github.com/NirAharon/BoT-SORT)、[FastReID](https://github.com/JDAI-CV/fast-reid)、[faster-whisper](https://github.com/SYSTRAN/faster-whisper)、[PySceneDetect](https://www.scenedetect.com/)。实施时固定具体模型仓库版本和权重校验值。代码仓库许可与预训练权重许可应分别核对；尤其不能直接把 [InsightFace 的公开人脸权重](https://github.com/deepinsight/insightface)当作可商用权重。

## 4. 处理流程

```text
本地视频
  ├─ FFmpeg：元数据、音轨、带时间戳的帧
  ├─ PySceneDetect：镜头边界
  ├─ RT-DETR → BoT-SORT：镜头内 tracklet
  │                    └─ FastReID：跨镜头候选合并 → P1/P2/未知
  ├─ faster-whisper：语音片段和文字
  └─ Qwen3-VL：分段事件候选
           ↓
  时间轴对齐、人物 ID 绑定、证据校验、去重
           ↓
  result.json + summary.md + 证据帧
```

### 4.1 预处理

- 保留视频原始时间戳；统一转换为秒数，展示时格式化为 `HH:MM:SS.mmm`。
- 镜头切分后，对每个镜头再按约 15–30 秒分段；长镜头使用 2 秒重叠，合并时去重。
- 视频理解的初始采样为 1 FPS；若发现快速操作或事件边界不清，对对应区间以较高采样率复查。人物跟踪使用单独的较高帧率，不与大模型采样率绑定。
- 记录每帧 `frame_id`、原始时间戳、镜头 ID；所有后续结果用这些键关联。

### 4.2 人物 ID

1. 对每个镜头运行人体检测和 BoT-SORT，生成局部 `track_id`、时间范围、检测框与代表帧。
2. 为各 tracklet 选取清晰、遮挡较少的代表帧，提取 FastReID 外观向量。
3. 对跨镜头 tracklet 计算相似度，同时检查时间冲突：同一时间不同位置出现的两个人不得合并为一个 ID。
4. 只合并超过高置信阈值且无冲突的候选；中间置信区间列为 `review_required`，低于阈值则建立新 ID。阈值不写死，使用标注样本校准并记录到配置。
5. 采用稳定排序分配 `P1`、`P2`（按首次出现时间）；保存局部 tracklet 到全局 ID 的映射与匹配证据。

外观重识别不是实名识别。同衣着、制服、换衣、背影、遮挡及低分辨率均可能误判。MVP 优先降低**错把两人合并**的风险，允许把同一人暂时拆成两个 ID，并在结果中标出待复核候选。

### 4.3 事件与任务抽取

- 给 Qwen3-VL 输入：视频片段、该片段人物轨迹的代表帧与局部编号、可用的语音转写、可选业务任务清单。
- 要求输出结构化候选：`start/end`、`actor_track_id`、`action`、`object`、`task_type`、`status`、`evidence_frame_ids`、`evidence_text_span`、`uncertainty_reason`。
- 模型只使用局部编号描述人物；后处理映射为全局人物 ID。不得让大模型自行决定跨镜头的同一人关系。
- `status` 只取 `观察到`、`进行中`、`已完成`、`无法判断`。`已完成` 必须有结果画面或明确语音证据；单纯动作开始不构成完成证据。
- 校验时间范围在原视频内、证据帧属于对应区间、人物确实出现在证据帧；不满足的事件降级为 `无法判断` 或进入待复核列表。
- 最终摘要由**校验后的事件列表**生成，不直接对整段视频自由发挥。

## 5. 对外接口与产物

CLI 约定：

```bash
video-demo analyze /data/example.mp4 --output /data/runs/example --model qwen3-vl-8b --task-config /data/tasks.yaml
```

`--task-config` 可省略；省略时抽取开放式动作，不承诺识别某行业特有任务。退出码：`0` 成功、`2` 输入错误、`3` 模型/环境错误、`4` 处理中断。失败时保留日志和已完成的中间产物，以便排查。

输出目录：

```text
run/
  result.json          # 机器可读结果
  summary.md           # 人可读摘要和时间线
  evidence/            # 被引用的关键帧
  tracks.json          # 局部轨迹及全局人物映射
  transcript.json      # 有语音时生成
  manifest.json        # 输入哈希、模型版本、参数、运行时间
  run.log
```

`result.json` 最小结构示例：

```json
{
  "schema_version": "1.0",
  "video": {"duration_ms": 68000},
  "people": [
    {"id": "P1", "first_seen_ms": 2400, "last_seen_ms": 61200, "review_required": false}
  ],
  "events": [
    {
      "id": "E1",
      "start_ms": 12000,
      "end_ms": 18500,
      "person_id": "P1",
      "action": "拿起工具并检查设备",
      "object": "设备",
      "task_type": null,
      "status": "观察到",
      "evidence": [{"timestamp_ms": 14320, "frame_id": "F1432", "image": "evidence/F1432.jpg"}],
      "review_required": false
    }
  ],
  "summary": "P1 检查设备；视频未显示该操作的完成结果。",
  "warnings": []
}
```

`person_id` 允许为 `null`，例如只看到手部操作或人物归属不明。模型分数可以作为诊断字段，但不向使用者展示为“真实概率”，也不把不同模型的分数直接相乘。

## 6. 质量验证与验收

先收集至少 20 段有使用权限的代表视频，覆盖：单人、多人同框、人物离开再出现、镜头切换、短暂遮挡、相似衣着、无语音、有语音、快速动作和低画质。人工标注人物对应关系、关键任务、时间范围及可见的完成证据。验证集与阈值校准样本分开。

MVP 验收分两级：

**工程闭环**

- 视频能够完整离线处理，产出可解析的 JSON、中文摘要、人物列表、事件时间线和证据帧。
- 所有事件时间戳在视频范围内；每个非语音事件至少有一处可定位的视觉证据。
- 人物跨镜头再次出现时，系统给出同 ID 或待复核结果；不静默强行合并。
- 输入损坏、无人物、无语音、模型加载失败时有明确结果或错误说明。

**效果指标（在标注集上报告，不预设模型必达）**

- 事件精确率、召回率；起止时间误差，按任务类型分别统计。
- 人物 IDF1 或同人配对准确率，以及“错合并”和“错拆分”数量。
- `已完成` 事件的证据支持率；无证据结论计为错误。
- 每分钟视频的处理耗时、峰值显存、产物大小。

是否进入下一阶段，以实际业务视频上的人工复核结果为准；不使用公开演示视频的单个成功案例作为验收。

## 7. 实施顺序

1. **最小闭环**：视频切段 → Qwen3-VL 事件 JSON → 时间线和摘要；先确认任务描述是否有价值。
2. **人物稳定性**：RT-DETR → BoT-SORT → FastReID，接入全局人物 ID 和待复核状态。
3. **声音与证据**：接入 faster-whisper、证据帧校验、报告生成。
4. **样本验证**：标注真实视频，校准阈值和片段长度，记录失败案例。

## 8. 主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 快速动作被低 FPS 采样漏掉 | 人物跟踪使用独立帧率；关键区间提高大模型采样率。 |
| 长视频显存和上下文开销过大 | 镜头/时间双重分段、限制每段帧数、必要时使用 4B 和量化。 |
| 反复出镜人物认错 | 跟踪与跨镜头重识别分开；时间冲突校验；不确定时待复核。 |
| 视频模型编造任务结果 | 结构化事件、证据帧、完成状态规则、最终摘要只引用已校验事件。 |
| 语音人物与画面人物混淆 | 语音先只作文字证据；MVP 不自动绑定说话人和画面人物。 |
| 开源许可不等于权重可商用 | 固定依赖与权重来源，发布或商用前逐项复核许可。 |
| 人物影像与轨迹数据敏感 | 默认本地存储、限制访问、提供删除整次运行产物的方式；MVP 不建实名库。 |

## 9. 待确认但不阻塞原型的问题

1. 确认项目 Python/CUDA/PyTorch 组合并完成服务器上的最小 GPU 推理测试；`nvidia-smi` 的 CUDA 13.0 是驱动支持的最高 CUDA 版本，不表示已安装对应 Toolkit。
2. 视频主要类型：固定摄像头、作业操作、会议、教学或剪辑短视频。
3. “任务”是否有预定义清单及完成标准。
4. 期望单视频最长时长、日处理量、可接受处理时间。

这些信息决定模型大小、采样率和验收样本，但不改变上述最小处理链路。
